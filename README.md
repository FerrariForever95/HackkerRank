# C++ Problem Solving — HackerRank

> Just stressing the L1 cache, L2 Cache of my brain to stress test to retrive what i have learnt.
 

A collection of my C++ problem-solving journey on HackerRank.

This repository contains the programs, experiments, mistakes, solutions, and progressively harder problems I encountered while working through C++ on HackerRank.

The goal isn't just to collect accepted solutions.

It's to understand how C++ behaves when the problems stop being straightforward.

## Problem-Solving Philosophy

I prefer understanding the mechanism behind a solution rather than treating HackerRank as a collection of code snippets.

For example:

```text
Problem
   ↓
Understand the data structure
   ↓
Understand the operation
   ↓
Identify the constraint
   ↓
Find the bottleneck
   ↓
Choose the appropriate C++ mechanism
   ↓
Implement
   ↓
Test
   ↓
Optimize if necessary
```

A solution that works is good.

A solution that works because you understand why it works is better.

## The Harder Part

Some of the later HackerRank C++ problems are less about writing an algorithm from scratch and more about understanding features of the language.

That's intentional.

C++ has a massive surface area.

Knowing:

```cpp
for(...)
```

is one thing.

Knowing when to use:

```cpp
std::map
std::deque
std::vector
templates
inheritance
virtual functions
operator overloading
dynamic_cast
```

is another.

And knowing when none of them are appropriate is another level entirely.
